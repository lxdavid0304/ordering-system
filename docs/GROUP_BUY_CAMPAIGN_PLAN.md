# 開團／湊單活動功能規劃書

## 1. 功能定位

新增一個「開團廣場」，讓已驗證的會員可以發起湊單活動；其他會員可先瀏覽活動條件，再決定加入並建立自己的採買清單。

這個功能的目的不是讓團主代替大家付款，而是把同一個採買目標、截止時間與交貨地點集中起來，讓大家更容易湊到免運、滿額或共同採買門檻。

建議名稱：**一起湊單**。

## 2. 使用情境

| 情境 | 範例 |
| --- | --- |
| 湊免運 | 團主發起「本週 Costco 補貨團」，總額達指定門檻即可成團。 |
| 固定交貨點 | 同一宿舍或社區住戶選擇同一個交貨地點，集中採買。 |
| 主題採買 | 發起「開學宿舍補貨」、「烤肉食材團」等主題活動。 |
| 截止日前補單 | 已有採買團尚未結單，會員可直接加入自己的商品。 |

## 3. 角色與權限

| 角色 | 可以做什麼 | 不可以做什麼 |
| --- | --- | --- |
| 訪客 | 瀏覽公開活動摘要 | 加入活動、查看參與者個資。 |
| 會員 | 建立、加入、退出自己的活動；管理自己的訂單 | 查看其他會員的訂單內容與電話。 |
| 團主 | 編輯尚未成團的活動、提前結束招募 | 修改其他會員的品項、付款或個資。 |
| 管理員 | 審核、下架、取消活動；統整採買 | 直接替會員付款或任意修改會員個資。 |

建議第一版採「**會員可發起、管理員可下架**」：保留社群彈性，也能處理惡意或不清楚的活動。

## 4. 第一版功能範圍（MVP）

### 4.1 發起活動

團主填寫：

- 活動名稱與一句說明。
- 預計結單時間。
- 交貨地點。
- 成團目標：最低參與人數、最低金額，或兩者皆可。
- 是否公開顯示參與人數與目前累積金額。
- 備註，例如「僅限明德樓」、「希望週五前收單」。

建立後狀態為「招募中」，並產生可分享的活動連結。

### 4.2 加入與填單

會員點擊「加入這一團」後：

1. 系統建立活動參與紀錄。
2. 直接帶到既有填單頁。
3. 自動帶入活動的交貨地點，並在訂單上綁定活動。
4. 會員仍只看得到自己的清單與付款狀態。

熱門商品、手動新增商品、收藏商品等現有功能可直接沿用。

### 4.3 活動進度

活動卡片顯示：

- 招募截止倒數。
- 目前參與人數／目標人數。
- 目前累積金額／目標金額（若團主選擇公開）。
- 交貨地點。
- 狀態標籤：招募中、已成團、已結單、採買中、可取貨、已結束、已取消。

### 4.4 成團與通知

- 達到門檻時，系統自動改為「已成團」並通知團主與參與者。
- 截止前 24 小時提醒尚未填單的參與者。
- 截止後鎖定新增參與者；團主或管理員可視規則決定是否允許既有會員補單。
- 管理員沿用既有訂單流程，將活動內訂單統一採買與更新狀態。

## 5. 建議頁面與操作流程

```text
LINE 圖文選單／網站入口
        ↓
一起湊單廣場（活動列表）
        ↓
活動詳情
  ├─ 加入這一團 → 填單頁（已帶入活動與交貨點）
  └─ 分享活動
        ↓
我的活動
  ├─ 我發起的團
  └─ 我加入的團
```

### 行動版設計

- 活動列表採單欄卡片，卡片頂部放截止倒數與狀態。
- 卡片中段只保留「人數、金額、交貨點」三個重點，避免資訊太密。
- 固定底部按鈕使用「加入這一團」；已加入時改為「前往我的清單」。
- 活動詳情內不公開姓名、電話與個別商品，只顯示統計數字。

## 6. 資料模型與後端規劃

### 新增資料表

| 資料表 | 重點欄位 | 用途 |
| --- | --- | --- |
| `group_campaigns` | `id`、`owner_id`、`title`、`description`、`delivery_location`、`deadline_at`、`min_participants`、`min_total_amount`、`status` | 活動主檔。 |
| `group_campaign_members` | `campaign_id`、`user_id`、`joined_at`、`status` | 活動參與者。 |
| `group_campaign_events` | `campaign_id`、`actor_id`、`event_type`、`payload` | 成團、結單、取消等稽核紀錄。 |

### 現有資料表調整

在 `orders` 新增可為空的 `campaign_id`，把每張會員訂單歸屬到活動。既有非活動訂單不受影響。

### RPC 與安全性

- `create_group_campaign(...)`：驗證會員資料完整、截止時間與交貨點。
- `join_group_campaign(...)`：確認招募中且未重複加入。
- `leave_group_campaign(...)`：僅允許尚未結單且未進入採買流程時退出。
- `get_group_campaign_summary(...)`：只回傳可公開的統計值。
- `close_group_campaign(...)`：團主或管理員操作，並寫入事件紀錄。

RLS 原則：

- 一般會員只能讀取公開活動與自己的參與紀錄／訂單。
- 團主不取得其他會員的訂單內容與個資。
- 管理員可讀取活動內訂單，以延續目前採買管理需求。

## 7. 狀態規則

| 狀態 | 進入條件 | 可進行操作 |
| --- | --- | --- |
| `recruiting` 招募中 | 團主建立活動 | 加入、退出、分享、團主編輯。 |
| `formed` 已成團 | 達成設定門檻 | 既有會員繼續填單；可依規則繼續加入。 |
| `locked` 已結單 | 截止時間到或團主結單 | 停止加入與修改。 |
| `shopping` 採買中 | 管理員開始處理 | 顯示處理進度。 |
| `ready_pickup` 可取貨 | 採買完成 | 發送既有取貨通知。 |
| `closed` 已結束 | 全部訂單完成 | 僅供查閱。 |
| `cancelled` 已取消 | 團主或管理員取消 | 通知參與者，保留事件紀錄。 |

## 8. 分期開發建議

### 第一階段：可用的開團體驗

- 活動建立、列表、詳情、加入／退出。
- `orders.campaign_id` 關聯。
- 招募中與已結單狀態。
- 行動版與 LINE 分享連結。

### 第二階段：自動化與後台整合

- 金額／人數門檻自動成團。
- LINE 成團、截止與取消通知。
- 後台依活動篩選訂單、匯出活動採買清單。
- 團主活動管理頁。

### 第三階段：社群與營運功能

- 團主信用／完成率。
- 重複開團範本。
- 候補名單與滿團通知。
- 活動留言或問答；需搭配檢舉與內容管理機制。

## 9. 風險與處理原則

| 風險 | 處理方式 |
| --- | --- |
| 有人開團後不處理 | 團主只能發起招募；採買與正式訂單流程仍由管理員管理。 |
| 個資外洩 | 活動頁不公開姓名、電話、個別訂單或付款資訊。 |
| 成團後有人退出 | 結單後鎖定退出；活動摘要即時計算有效訂單。 |
| 目標未達成 | 截止後標示未成團，由團主或管理員選擇取消或照常採買。 |
| 活動洗版／惡意內容 | 建立頻率限制、檢舉功能與管理員下架權限。 |

## 10. 需要先確認的產品決策

1. 未達門檻的活動，是否允許照常採買？
2. 團主是否可以指定「只限特定交貨點」或「只限受邀者」？
3. 付款是否繼續由每位會員各自處理？建議第一版維持個別付款。
4. 團主能否代其他人填單？建議不開放，以降低個資與帳務風險。
5. 是否先限定「管理員可開團」，待流程穩定後再開放所有已驗證會員？

## 結論

建議先做「**會員可發起、每人各自填單、管理員集中採買**」的 MVP。這能直接利用現有訂單、付款、交貨與 LINE 通知流程，開發風險最低，也能先驗證大家是否真的有湊單需求。
